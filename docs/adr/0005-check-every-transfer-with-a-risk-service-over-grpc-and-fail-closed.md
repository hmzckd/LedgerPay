# Check every transfer with a risk service over gRPC and fail closed

Before LedgerPay writes a deposit or a transfer, it asks a separate service, LedgerPay.Risk, whether the money may move. The two services talk over gRPC, with the contract in one `protos/risk.proto` file from which each side generates its own code, so a renamed field or a wrong type is a build error instead of a surprise at run time. The call has a one second deadline and is made before the database transaction starts, because a slow network call while the sender account is locked would make every other transfer from that account wait too. If the risk service rejects the transfer, the client gets `422`. If it is down, too slow, fails in any other way, or answers without a decision, the transfer is refused with `503` and no money moves. This "fail closed" choice means an outage of the risk service stops deposits and transfers, which we accept: moving money that nobody checked is worse than asking the client to try again later with the same Idempotency-Key.
